Settles the "exact permissions TBD" in PRD 4 | Developer decision, recording what the code already enforces (`src/lib/tenant.ts`, `src/lib/tickets/scan-server.ts`) |
| 2026-10-14 | Morale candidates and free votes ship **with public disclosure**: public results label morale candidates and show free votes as a figure separate from paid votes; morale candidates and free votes are flagged in every admin view and report; the platform and organization switches default to on and the organizer opts in per event; the super admin can still disable either feature per organization or platform-wide. Settles #29 | Developer decision: disclosure keeps the feature honest to voters while giving organizers the competitive-looking categories the partner asked for |
| 2026-11-12 | Payouts stay as built: the organizer requests a payout whenever they choose, to MoMo or a bank account; the super admin approves or rejects it, transfers the money outside the platform and marks it paid, which is what debits the ledger. Settles #3 | Developer decision, recording what the code already does (`src/lib/payouts-server.ts`) |
| 2026-11-12 | Results visibility has no default: the organizer chooses one of `hidden`, `ranking`, `percentage` or `count` when creating the event. Settles the defaults half of #26; the real-time approach stays open | Developer decision, recording what the code already does (`src/lib/events-server.ts`) |
| 2026-11-12 | Ticket scanning is a web page in the dashboard (no separate app or PWA): staff use the phone camera through the browser's built-in QR detector, or paste the ticket code or link. Settles #34 | Developer decision, recording what the code already does (`src/components/tickets/Scanner.tsx`, `src/lib/tickets/scan-server.ts`) |
| 2026-11-12 | The cumulative report is the superset of the options: per category and per nominee, one column per round, paid and free votes shown separately, morale candidates flagged, the organizer's name and logo, and a "provisional" note while any round is open; available from the event page at any time as a PDF. Settles #35 | Developer decision, recording what the code already does (`src/lib/report/`) |

| 2026-11-12 | Data protection, partly: ticket buyers' phone numbers are masked to the last three digits (`maskPhone` in `src/lib/phone.ts`) on the door scanner, on the ticket page and for every role except owner and admin; only owners and admins see full numbers, on the event page. Settles part of #28; retention periods and consent stay open | Developer decision.
